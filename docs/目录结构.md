# 目录结构

## 工具层

- 根目录 `*.py`：当前兼容结构下的运行模块。现阶段保持平铺导入，避免为移动文件制造大范围无功能改动。
- `启动小说工具.pyw`：桌面入口。
- `book_runner.py`：GUI 和无界面入口共用的批次生命周期、边界与异常暂停控制器。
- `headless_app.py`：不创建 Tk 窗口的生产流程兼容适配器。
- `novel_cli.py`：只读状态查询、严格只读 `doctor` 和显式授权的有界批次命令行入口。
- `tests/`：自动化测试。
- `skills/`：运行时加载的 JSON 技能定义。
- `.tools/`：工具自带依赖，不得当作缓存删除。
- `.runtime/`：最近打开项目等可再生 GUI 状态。
- `docs/HANDOVER.md`：当前权威交接入口。
- `docs/开发状态.md`：已实现能力、当前边界和下一步。
- `docs/`：其余通用说明与路线图。
- `research/`：扫榜和选题研究资料。

## 项目层

每本书只在 `projects/项目名/` 下维护自己的资料：

- `characters/`：人物设定。
- `world_building/`：世界观和规则。
- `plot/`：商业蓝图、大纲、进度、状态台账和提交回执。
- `rewrite_staging/`：待审候选稿。
- `output/`：正式工作正文。
- `publish/`：正式发布镜像。
- `logs/`：运行日志和模型用量。
- `history/`：历史版本。

## 不应混放

- 通用说明不记录具体某本书的实时章数。
- 扫榜资料不放在 `projects/`，也不作为正文正式来源。
- Python 缓存和测试缓存不属于工具资产，可随时重新生成。
- 小说正文、平台发布状态和账号数据不放进工具根目录。

## 后续代码整理边界

批次启动、线程异常和项目锁释放已经抽到 `book_runner.py`。下一阶段继续抽取单章工作流和批次状态存储，再考虑把平铺模块迁入 `src/`。在正文生成方法尚未解耦前直接移动全部模块，收益小且容易破坏入口、测试和本地依赖加载。
