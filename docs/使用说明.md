# 工具使用说明

## 运行环境

- 双击入口使用系统当前 `.pyw` 关联；本项目实际依赖按 Python 3.14 打包。
- 命令行统一使用 `py -3.14 -X utf8 -B`，不要用 Python 3.12 启动 GUI。
- 接手或排障先读 `docs/WORKLOG.md`，再读 `docs/HANDOVER.md` 和 `docs/开发状态.md`。改动完成后必须同步更新工作台账和相关状态文档。

## 日常操作

1. 双击根目录的 `启动小说工具.pyw`。
2. 选择已有项目，或点击“新建一本”填写新书信息。
3. 点击主生成按钮。
4. 需要停止时点击“暂停”；下次从正式断点继续。
5. 在“单章复制”页选择来源和章号，再复制整章或正文。

## 稿件状态

- `rewrite_staging/`：完整但尚未正式放行的候选稿。
- `output/`：通过正式提交的工作正文。
- `publish/`：通过发布镜像检查的正文。

复制页里的“最新稿”可能优先显示某个模型生成的候选稿。候选稿能被查看或复制，不代表它已经正式提交或发布。

## 工具自动处理的内容

工具会处理商业策划、大纲、逐章写作、格式和设定检查、有限重写、人物状态、时间线、伏笔、长期记忆和断点恢复。闸门章节及失败后的行为以当前项目的 `project_config.json` 为准。

## 查看单本书状态

每本书的文档用于交接，实时结论还要用正式目录和 `doctor` 刷新。接手单书时依次查看：

- `projects/项目名/当前状态.md`
- `projects/项目名/plot/写作进度.md`
- `projects/项目名/output/`
- `projects/项目名/publish/`
- `projects/项目名/plot/runtime/commit_receipts/`

`output/` 中连续存在的最高正式章节，是本地续写边界；候选区不能作为续写断点。文档与正式目录、收据或 `doctor` 冲突时，先查清并更新文档，再开始改动。

## 严格只读体检

```powershell
py -3.14 -X utf8 -B novel_cli.py doctor --project "projects/项目名"
```

`doctor` 只读取文件并输出 JSON，不调用模型、不恢复事务、不迁移配置、不重建派生状态。结果为 `FAIL` 时退出码为 `2`，完整报告仍会输出。GUI 的“详细体检”可能执行安全恢复，不能替代严格只读 `doctor`。

## 当前项目边界

- `高武法医_死者教我最后一招`：300章完结封存，禁止第301章。
- `整理遗物时_我收到了失踪姐姐的委托`：120章完结封存，禁止第121章。
- `足球_百次复盘我成了世界中场`：截至2026-08-28的实测边界为第1—60章正式正文与第1—60章发布镜像，审修后 `doctor PASS`；下一章为第61章。后续以项目状态文档和实时体检为准。

两本完结书的旧派生状态或状态账本告警只保留为历史证据，不自动修复，也不能据此改正文。足球项目的准确续写边界以项目交接、写作进度、`output/` 和 `doctor` 为准。

## 正式尾段重写

连续重写当前正式尾段时，工具会建立全量回滚快照，并按章重新走正式审查与提交。已通过的模型预检保存在项目 `.runtime/formal_suffix_preflight_cache/`；晚章失败回滚后，只有正文、前置状态、模型、配置、上下文和代码指纹全部一致的结果才会复用。缓存命中只减少重复模型调用，不跳过本地校验、证据复核或商业闸门。
