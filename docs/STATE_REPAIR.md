# 状态审查与恢复边界

## 正常修复

提取状态失败只修状态，不重写正文。补丁只能修改被拒绝条目或追加被指出的遗漏，其他条目保留；已知类别的空数组是无操作。漏核心事件可补events，章号只按程序的可信当前章号修正。修后仍需确定性校验和独立证据审计。

正文重写只依据经过引文验证且pass=false的draft拒绝；reject/missing超过40条整体拒收。模型返回不等于审查通过，心跳也不代表有新输出。

## 停止条件

- STATE_REPAIR_STOPPED：同一绑定重复回到失败状态，或默认累计6轮未通过。原稿和失败历史保留，先核对提取规则及审计反馈。
- STATE_REPAIR_STORAGE_FAILED：失败记录存储检查、写入或读回失败。修复存储后必须补存真实失败记录，不能仅凭小探针可写就解除锁。

空响应也占用失败预算。超长响应可以省略提示中的原始文本，但保留摘要、问题及失败历史。更换提供商或修改代码导致绑定变化需要重新验收，不证明旧失败已经解决。

## 待补存记录

写真实拒绝记录前登记PENDING标记。原实例有内存副本时，可在存储恢复后补存并核对；若实际记录已落盘而仅标记收尾中断，新实例可按摘要恢复。若重启丢失了从未落盘的原记录，仅有标记，则保持暂停，需要恢复原记录，不能删标记求通过。

PENDING、REJECTED历史、待审稿保留标记及损坏记录不参与普通审批缓存的6份轮转淘汰。普通审批缓存仍受数量约束；恢复证据需另行人工核验后归档。

## 验证范围

本次用临时目录和模型替身验证恢复、权限、次数和异常分支，不调用真实模型。生产调用、服务可用性和GUI视觉验收仍是独立验证项。
