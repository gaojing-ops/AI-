# 小说工具（纯净版）

输入一本书的基本设定，完成策划、逐章写作、检查、记忆更新和断点续写。

## 开始使用

1. 双击 `启动小说工具.pyw`。
2. 选择已有项目，或新建一本书。
3. 使用主按钮开始生成；需要停止时点击“暂停”。
4. 重新打开后，工具从正式断点继续。

接手工具必须先读 [当前工作台账](docs/WORKLOG.md)，再读 [项目交接](docs/HANDOVER.md) 和 [开发状态](docs/开发状态.md)。任何完整改动批次结束后，都要立即更新工作台账及受影响的状态文档；详细规程见根目录 `AGENTS.md`。操作说明见 [使用说明](docs/使用说明.md)，后续重构安排见 [优化路线图](docs/优化路线图_GitHub复核版.md)。

## 正式生成链

```text
新书设定
→ 商业策划与故事圣经
→ 人物、世界观和滚动细纲
→ 生成候选章
→ 硬规则与连续性检查
→ 内容及商业审查
→ 正式提交
→ 更新事实、人物、时间线、伏笔和长期记忆
→ 下一章
```

失败稿只能留在候选区，不能进入正式正文。具体闸门、批次和目标章数由每本书的 `project_config.json` 决定。

## 根目录

- `projects/`：每本书的独立项目和正式产物。
- `docs/`：通用使用说明、目录说明和优化路线图。
- `research/`：扫榜等研究资料，不作为正文来源。
- `skills/`：工具运行时读取的 JSON 技能配置。
- `tests/`：自动化测试。
- `.runtime/`：上次项目等可再生运行状态。
- `.tools/`：本地 Python 依赖和 Codex 运行环境，运行代码依赖它，不要删除。

完整目录规则见 [目录结构](docs/目录结构.md)。

## 无界面入口

只读查看当前正式进度：

```powershell
py -3.14 -X utf8 -B novel_cli.py status --project "projects/项目名"
```

严格只读体检（检查正式正文、发布镜像、正史/事实库/状态账本和待恢复提交；不调用模型、不恢复事务、不写入报告）：

```powershell
py -3.14 -X utf8 -B novel_cli.py doctor --project "projects/项目名"
```

`doctor` 始终把 JSON 输出到标准输出，可由调用方按需保存：

```powershell
py -3.14 -X utf8 -B novel_cli.py doctor --project "projects/项目名" > doctor-report.json
```

结果为 `FAIL` 时命令返回退出码 `2`，但仍会输出完整报告，便于自动化收集故障证据。

运行明确终点的正式批次：

```powershell
py -3.14 -X utf8 -B novel_cli.py run `
  --project "projects/项目名" `
  --expected-latest 0 `
  --to 15 `
  --execute
```

`run` 不带 `--execute` 时必定拒绝写入。启动前还会检查正式章节连续性、当前章是否与 `--expected-latest` 一致以及项目健康状态。无界面入口与桌面 GUI 共用 `book_runner.py` 的批次生命周期，不再依赖一次性运行脚本。
